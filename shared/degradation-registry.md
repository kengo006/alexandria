# Degradation registry (template)

A machine-readable, honest list of text-layer files that have been **repaired to their ceiling and are still not grep-reliable**. The registry exists because of one principle:

> **A file you could not fully fix is registered, never hidden.** Hiding it turns every future grep miss on that file into a confident, wrong "it's not in the vault."

Some sources never yield a clean text layer — a hostile scan, a font with a private encoding, a language your OCR mishandles. Repair what can be repaired (see `roles/librarian.md` §8); what remains gets a registry entry stating exactly **which access paths still work**. The searching roles consult the registry before shipping any negative conclusion (`roles/searcher.md` §1).

## Schema

One JSON file, regenerated by the Librarian whenever a repair batch lands — a **living file**: consumers read it fresh, never cache it, never copy its numbers elsewhere.

**It is not one list.** A registry begins life as "the files whose grep lies", and then the corpus teaches you that files fail in more than one way — and that the ways prescribe *different, sometimes opposite* actions. Keep them in separate keys:

| Key | What it says about the file | What a searching role must do |
|---|---|---|
| `unreliable_recall` | the text layer is damaged; grep misses what is actually there | **A zero hit count proves nothing.** Change file, change wording, or use another access path |
| `unreliable_order` | the text is intact, the *reading order* is scrambled (2-up scans, rotated pages, column mis-threading) | **Grep normally — and a zero hit count still counts.** But never trust what sits *beside* a hit: no context reading, no continuous quotation |
| `not_citable` | recallable, but there is no citable original behind it (a web capture, an internal digest) | Use it for leads. **Never as a citation source, never with a page number** |
| `delisted` | repaired; no longer degraded | Off the active list — **but read the entry**: it may record a limit that survived the repair |

🔑 **The first two prescribe opposite things.** One says a zero result is meaningless; the other says a zero result is trustworthy. Collapse them into a single `degraded` flag and you have told a searching role to distrust a grep that is, on that file, completely reliable — and you will not find out, because distrust produces no error.

```json
{
  "version": 3,
  "generated": "2026-07-20T12:00:00",
  "generator": "corpus QA pipeline (see roles/librarian.md §8)",
  "counts": { "unreliable_recall": 2, "unreliable_order": 1, "not_citable": 0, "delisted": 1 },
  "unreliable_recall": [
    {
      "rel": "memory-studies/Doe_2011_Archives of Memory.txt",
      "why": "ceiling — hostile scan; diacritics collapse under OCR",
      "usable": { "semantic": true, "grep": false },
      "note": "grep is unreliable on this file (0 hits != absent); semantic recall and page rendering still work"
    },
    {
      "rel": "memory-studies/Roe_1998_Commemoration and Its Discontents.txt",
      "why": "fixing — residual word-gluing, re-OCR queued",
      "usable": { "semantic": true, "grep": false },
      "note": "temporary entry; moves to `delisted` when the repair batch lands"
    }
  ],
  "unreliable_order": [
    {
      "rel": "memory-studies/Poe_2005_On Assembly.txt",
      "why": "2-up scan, rotated; blocks interleave — line order within a page is not reading order",
      "verified_pages": ["p.208 / p.209 (image-checked)"],
      "usable": { "grep": true, "adjacency": false, "continuous_quotation": false },
      "note": "grep hits are real and a zero count still counts; never quote across lines, never read context from this file"
    }
  ],
  "not_citable": [],
  "delisted": [
    {
      "rel": "memory-studies/Ives_2014_Ruins and Registers.txt",
      "delisted": "2026-07-18",
      "why": "re-extracted; word-gluing resolved",
      "residual": "the extractor drops an occasional whole paragraph on this file (one confirmed, printed p.94; never counted systematically) — verbatim quotation still goes back to the page image"
    }
  ]
}
```

*(All rows are illustrative placeholders — replace with your own.)*

⚠ **`verified_pages` is not decoration.** What enters the registry must be *verified*, not presumed. A file appearing on a "these are 2-up scans" worklist is neither evidence that its reading order is broken nor evidence that it is fine; only someone who looked knows. Rows without an anchor do not go in.

## Iron rules

- **Every entry carries its usable paths.** "Degraded" never means "unusable" — it means *which* access path lies. A file whose grep lies but whose semantic recall works is still a working source; the registry is what keeps it one.
- **Each count must equal its own category's actual row count.** A generator that writes a count it didn't measure is manufacturing a credential; consumers that detect a mismatch report the measured value and flag the discrepancy — they do not silently pick one.
- **A new key earns its place only when the action it prescribes differs from every existing key's.** Same action, different flavour of damage ⇒ that is a field inside an entry, not a category. This is the whole test; "it feels like a different problem" is not.
- 🔴 **A key with no members is not a schema, it is a guess.** One was opened here for "sources with no page anchors at all" and retracted the same day: the book that prompted it had 294 of them, under a marker shape the detector had never been written to look for — **the zero was the detector's range, not the book's property**. The rule that admits *entries* applies to *keys*: what goes in must be verified, not presumed. An empty key is worse than an empty list, because the next reader takes its existence as evidence that such files are known to exist.
- **Delisting ends the degradation, not the entry.** A repaired file keeps its row under `delisted` with whatever limit outlived the repair. "It came off the list" is the most natural thing in the world to read as "it is fine now", and that is exactly the sentence the registry exists to prevent.
- **Entries are states, not verdicts.** `fixing` entries drop off when their repair lands; `ceiling` entries stay until the source itself is replaced. Regenerate, don't hand-edit.
- **The searching roles' obligation is mechanical**: before any "not in the corpus / nowhere in this work" conclusion, check the file against the registry. Listed = grep silence is not evidence; use the paths marked usable.

## The index self-report (closing the loop)

A registry only the humans read will be skipped. Wire it into the search index itself, so a searching agent learns *from the tool it is already holding* that some files' silence means nothing. The contract lives in `optional-integrations.md` §2; it has two non-negotiables.

> **Unreadable registry → `status: "unknown"`, never `0`.** "Zero degraded files" asserts that negative conclusions are safe everywhere; "I could not read the registry" asserts nothing. Collapsing the second into the first makes the agent boldest exactly when it should be most careful.

> **Report every category by name, not one number.** An endpoint that answers `degraded_files: 3` while the registry holds four categories has told the agent a quarter of what it needs — and has quietly told it the *wrong* thing about the other three, because "not on the degraded list" then reads as an all-clear for conditions the list never covered. Emit each key with its size; if you can afford one more field, carry each key's one-line instruction alongside it.

🔑 **The reason this is a contract and not a nicety**: the only route to the searching role that is guaranteed to be taken is **the tool it is already using**. Anything that depends on the role remembering to open a JSON file is a route that will sometimes not be taken, and its failures are silent. Observed here: a file was moved into `unreliable_order` and the tool's self-report — reporting a single count from a single key — did not change by one character.
